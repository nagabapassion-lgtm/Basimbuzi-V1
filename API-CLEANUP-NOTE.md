# THE LOGIN / "FUNCTION INVOCATION FAILED" FIX — read this first

## What was actually wrong

Your last deployment answered every `/api/...` request with:

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/var/task/lib/backend/router'
imported from /var/task/api/router.js
```

That single error broke **everything at once** — the login, the dashboard, the
public site, all of it, because they all call the same one API function.

**Root cause (reproduced and verified locally with the real Vercel builder):**
Vercel compiles each TypeScript file in `api/` one-by-one and keeps your import
lines exactly as written. Because the project was set up as an ES module
project, the compiled function used Node's ESM loader, and Node's ESM loader
**never guesses file extensions**. So the compiled line
`import { routeApiRequest } from '../lib/backend/router'` pointed at a path
that doesn't literally exist (`/var/task/lib/backend/router` — no `.js`), and
the function crashed on every single invocation, before any of your code ran.

## What this fix does

The build step now **bundles the whole API into one self-contained
plain-JavaScript file** (`api/router.js`, generated by `npm run build` — it is
not committed to git). The deployed function has **zero relative imports**,
so there is nothing left for the lambda to mis-resolve. This was verified
end-to-end locally:

- `vercel build` output inspected: single file, only `node_modules` beside it.
- The deployed artifact itself was executed: health → 200, login → clean JSON,
  unknown routes → 404, **9/9 simulated requests passed**.
- Typecheck clean, all 32 tests pass, frontend build unaffected.

Your URLs, handlers, data, and `vercel.json` rewrites are all unchanged.
