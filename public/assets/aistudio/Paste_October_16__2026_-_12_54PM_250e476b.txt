# SC Basimbuzi Management Portal & Digital Club Ecosystem
## Comprehensive System Architecture, Component Directory, and Operational Guide

---

## 1. Executive Summary & Club Profile

**SC Basimbuzi** is an established football club with professional aspirations, an active supporter community, multi-tier squad structures, and structured governance. To manage club administration, finance, member coordination, player agreements, and digital communications efficiently, the **SC Basimbuzi Digital Club Platform** serves as the central operating system.

This platform provides:
1. **Official Supporter & Public Web Hub**: Match fixtures, league standings, club news, supporter surveys, merchandise purchases, and online membership registration.
2. **Member Self-Service Portal (`/me`)**: Passwordless email magic code login, subscription dues status tracking, automated payment receipts, digital membership cards, and profile updates.
3. **Executive & Operational Administration (`/admin`)**: Financial accounting and double-entry ledger, digital receipting, expense disbursement vouchers, player contracts with two-party digital signing, merchandise order fulfilment with real-time pending alerts, and a collaborative drag-and-drop report canvas.
4. **Dedicated Windows Desktop Client (`desktop-win`)**: C# .NET WinForms wrapper with Microsoft Edge WebView2, automated WhatsApp reminder dispatch for subscription dues, and offline support.
5. **Resilient Security & Offline Sync**: Two-factor staff authentication (Password + 6-digit email OTP gate with 15-minute inactivity timeout), Service Worker PWA support, IndexedDB mutation queues, and automatic sync upon network recovery.

### Core Technology Stack
- **Frontend SPA**: React 18, TypeScript, Vite, Tailwind CSS, Lucide React Icons.
- **Reporting Engine**: HTML5 Canvas / SVG interactive report builder (`src/components/report-canvas`), PDF export via `jspdf` and `html2canvas`, QR code generation via `qrcode.react`.
- **Offline & Cache**: Service Worker (`public/sw.js`), IndexedDB local queue (`idb`), offline transaction replay.
- **Backend**: Supabase (PostgreSQL 15) with Row Level Security (RLS) and custom database triggers.
- **Serverless API**: 16+ Deno TypeScript Edge Functions (`supabase/functions/*`).
- **Object Storage**: Cloudflare R2 (S3-compatible API) for receipts, vouchers, contracts, and documents.
- **Email Service**: Brevo API via HTTPS with branded SC Basimbuzi responsive HTML email templates.
- **Desktop Application**: C# .NET WinForms wrapping Microsoft Edge WebView2 runtime with NSIS installer.

## 3. Configuration & Required Secrets

Configuration is split into **Client-side environment variables** (bundled into the Vite build) and **Server-side secrets** (stored securely in Supabase and accessed exclusively by edge functions).

### 3.1 Client-Side Environment Variables (`.env.local`)

These variables are defined in the frontend root `.env.local` file:

```env
# Supabase Connectivity
VITE_SUPABASE_URL=https://<your-supabase-project-id>.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...

# Club Identity & Branding
VITE_CLUB_NAME="SC Basimbuzi"
VITE_SUPPORT_EMAIL="support@basimbuzi.club"
VITE_LOGO_URL=https://pub-r2.basimbuzi.club/crest.png

# Application URL (Canonical domain for links, QR codes, and email references)
VITE_APP_URL=https://portal.basimbuzi.club

# Bot Protection
VITE_TURNSTILE_SITE_KEY=0x4AAAAAA...
```

| Variable | Required | Description |
|---|---|---|
| `VITE_SUPABASE_URL` | **Yes** | HTTPS URL of the SC Basimbuzi Supabase project |
| `VITE_SUPABASE_ANON_KEY` | **Yes** | Anonymous API key. Protected by Row Level Security on all tables |
| `VITE_LOGO_URL` | **Yes** | Direct URL to the official SC Basimbuzi crest image (used in app, PDFs, and emails) |
| `VITE_APP_URL` | Optional | Base URL for generated links. If left blank, falls back to `window.location.origin` |
| `VITE_TURNSTILE_SITE_KEY` | Optional | Cloudflare Turnstile public key for public forms bot protection |
| `VITE_CLUB_NAME` | Optional | Club display name (defaults to "SC Basimbuzi") |
| `VITE_SUPPORT_EMAIL` | Optional | Support email address displayed in help texts and error screens |

## 4. Role-Based Access Control (RBAC) & Security Policy

SC Basimbuzi enforces granular role privileges at both the database level (PostgreSQL RLS policies) and the application level (route guards and component permissions).

### 4.1 Roles & Permission Matrix

| Role (`UserRole`) | Designation | Permitted Areas & Capabilities |
|---|---|---|
| `L1_ADMIN` | Executive System Administrator | Full unconstrained access to all modules, system settings, database management, and user provisioning. |
| `L1_PRESIDENT` | Club President | Full executive oversight, financial reports, contract approvals, vouchers, members, team, and official sign-offs. |
| `L1_SECRETARY` | Club General Secretary | General administration, official records, member communications, team rosters, contracts, and documents. |
| `L1_TREASURER` | Club Treasurer | Financial ledger, payment vouchers, receipt generation, subscription tracking, and merchandise revenue. |
| `L2_ADMIN` | Finance & Operations Officer | Day-to-day bookkeeping, receipt issuing, expense voucher preparation, and order fulfillment. |
| `L3_ADMIN` | Team Operations Manager | Squad lists, player registration, contract preparation, match statistics, and team surveys. |
| `L3_COACH` | Head Coach / Technical Staff | Squad roster view, player technical and physical statistics, and team notices. |
| `L3_CAPTAIN` | Team Captain | Squad views, matchday logistics, and survey participation. |
| `L4_ADMIN` | Media & Communications Officer | Public website content management only (`/admin/site`). Redirected automatically away from administrative sections. |
| `COORDINATOR` | Membership Coordinator | Dedicated access to the member register (`/admin/members`), dues tracking, member import/export, and reminder queues. |
| `MEMBER` | Club Member / Supporter | Self-service access only via `/me` with passwordless email OTP verification. |

### 4.2 Two-Factor Staff Authentication & Session Security
1. **Password + 6-Digit Email OTP Gate (`TwoFactorGate.tsx`)**:
   - Staff login at `/admin` requires valid email and password credentials.
   - Upon credential validation, the `staff-login` Edge Function dispatches a 6-digit OTP code to the official's registered email address (valid for 10 minutes).
   - PostgreSQL RLS enforces that staff-level data is inaccessible until the code has been verified (Patch 015).
2. **Remember Me Feature**:
   - Allows officials on trusted devices to store their email identifier locally, streamlining the return login process while still requiring password and OTP verification.
3. **15-Minute Inactivity Auto-Lock (`IdleGuard.tsx`)**:
   - Monitors user interaction (pointer, keyboard, touches). If idle for 15 minutes, the active session is securely cleared.

## 5. Application Pages & Navigation Routes

### 5.1 Public & Supporter Pages

#### 1. Public Homepage (`/`)
- **File**: `src/views/PublicHome.tsx`
- **Audience**: General public, fans, prospective sponsors.
- **Features**: Hero announcement banner, official SC Basimbuzi crest, latest match results, upcoming fixtures, league standings table, sponsor showcases, and quick links to member registration and merchandise orders.

#### 2. Public Member Registration (`/member?page=form`)
- **File**: `src/views/MemberRegistration.tsx`
- **Audience**: Supporters joining SC Basimbuzi.
- **Features**:
  - Cloudflare Turnstile anti-bot verification.
  - Form validation for full name, email, phone number, physical address, and membership tier.
  - **Duplicate Prevention**: If the submitted email exists in the database, the user is notified:
    *"The email you are trying to register is already registered for another user. Please email the admin [here](mailto:secretary.akachaifc@gmail.com?cc=agkelvins004@Gmail.com) or contact via [WhatsApp](https://wa.me/256708344240)."* (configurable for SC Basimbuzi).
  - Triggers a branded welcome email via Brevo upon successful submission.

#### 3. Member Self-Service Portal (`/me`)
- **File**: `src/views/MemberPortal.tsx`
- **Audience**: Registered club members.
- **Authentication**: Passwordless email magic code.
- **Features**:
  - Personal profile and contact information.
  - Current season subscription dues status (Paid, Partial, Overdue).
  - One-click PDF receipt downloads for past subscription payments.
  - Digital membership card rendering with verified QR code.

#### 4. Public Merchandise Store (`/order`)
- **File**: `src/views/PublicOrder.tsx`
- **Audience**: Fans and supporters purchasing official club kits and apparel.
- **Features**:
  - Kit selection (Home, Away, Third, Training kits).
  - Sizing options (XS, S, M, L, XL, XXL) with custom back-printing (Player Name & Jersey Number).
  - Delivery location selection with automatic delivery fee calculation.
  - Payment proof attachment upload and automated order confirmation emails.

#### 5. Dynamic Public Surveys (`/survey/:slug`)
- **File**: `src/views/PublicSurvey.tsx`
- **Audience**: Supporters and stakeholders responding to official polls.
- **Features**: Dynamic slug routing (e.g., `/survey/player-of-the-month`), support for rating scales, single/multiple-choice questions, long text feedback, and automated closed-state messaging.

#### 6. Not Found Page (`*`)
- **File**: `src/views/NotFound.tsx`
- **Audience**: Any visitor accessing an invalid route. Displays branded 404 guidance back to home or the portal.

### 6.5 Database Migration Patches (`patches/`)

The database evolves through sequential SQL patches applied to PostgreSQL:

- `001_survey_slugs.sql`: Adds unique URL slugs and active status flags to club surveys.
- `002_lock_down_access.sql`: Core security hardening. Revokes public access to base tables and installs strict Row Level Security (RLS) policies.
- `003_subscriptions.sql`: Adds subscription tiers, amounts, and tracking to the members table.
- `004_broadcast_otp.sql`: Implements one-time verification tokens for administrators sending bulk broadcasts.
- `005_transitional_public_access.sql` & `006_remove_transitional_access.sql`: Controlled migrations during database hardening.
- `007_team_table_grants.sql`: Grants granular permissions to team staff for player rosters.
- `008_service_role_grants.sql`: Grants internal service-role privileges for serverless edge functions.
- `009_audit_log.sql`: Creates the immutable `audit_logs` table and triggers on all core operational tables.

## 7. Step-by-Step Deployment & Migration Guide for SC Basimbuzi

### 7.1 Database Initialization
1. Create a new PostgreSQL instance on Supabase.
2. In the Supabase SQL Editor, run `schema.sql` to construct the baseline schema.
3. Sequentially execute patches `patches/001_survey_slugs.sql` through `patches/022_coordinator_role_and_staff_audit.sql`.
4. Verify that Row Level Security is active on all tables:
   ```sql
   SELECT tablename, rowsecurity FROM pg_tables WHERE schemaname = 'public';
   ```

### 7.2 Edge Functions Deployment
1. Install Supabase CLI: `npm install -g supabase`
2. Link your project: `supabase link --project-ref <your-supabase-project-id>`
3. Set all required server-side secrets (refer to Section 3.2):
   ```bash
   supabase secrets set BREVO_API_KEY="..." BREVO_SENDER_EMAIL="notifications@basimbuzi.club" BREVO_SENDER_NAME="SC Basimbuzi" ...
   ```
4. Deploy all edge functions without JWT verification (the functions perform their own verification):
   ```bash
   for func in $(ls supabase/functions); do
     if [ "$func" != "_shared" ]; then
       supabase functions deploy $func --no-verify-jwt
     fi
   done
   ```

### 7.3 Cloudflare R2 Storage Setup
1. In the Cloudflare Dashboard, create an R2 bucket named `sc-basimbuzi-storage`.
2. Navigate to **R2 > Settings > CORS Policy** and paste the following configuration:
   ```json
   [
     {
       "AllowedOrigins": [
         "https://portal.basimbuzi.club",
         "https://basimbuzi.club",
         "http://localhost:3000"
       ],
       "AllowedMethods": ["GET", "PUT", "POST", "HEAD"],
       "AllowedHeaders": ["*"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```
3. Generate R2 API tokens (Access Key ID and Secret Access Key) and set them in your Supabase secrets.

### 7.4 Web Portal Build & Deployment
1. Set up the production `.env.local` with the values for SC Basimbuzi:
   ```env
   VITE_SUPABASE_URL=https://<your-project>.supabase.co
   VITE_SUPABASE_ANON_KEY=<your-anon-key>
   VITE_APP_URL=https://portal.basimbuzi.club
   VITE_LOGO_URL=https://pub-r2.basimbuzi.club/crest.png
   VITE_TURNSTILE_SITE_KEY=<your-turnstile-site-key>
   VITE_CLUB_NAME="SC Basimbuzi"
   VITE_SUPPORT_EMAIL="support@basimbuzi.club"
   ```
2. Run linting and unit tests:
   ```bash
   npm run lint
   npm test
   ```
3. Compile the production build:
   ```bash
   npm run build
   ```
4. Deploy the `dist/` directory to Vercel, Cloudflare Pages, or any modern web host. Ensure all routes are rewritten to `/index.html`.

### 7.5 Windows Desktop Installer Build
1. Update `desktop-win/app.config.json` with the production portal URL:
   ```json
   {
     "appUrl": "https://portal.basimbuzi.club/admin"
   }
   ```
2. Update the club name and icons in `desktop-win/AkachaiPortal.csproj` and `desktop-win/installer.nsi` to reflect **SC Basimbuzi**.
3. Run the installer build script:
   ```powershell
   powershell -ExecutionPolicy Bypass -File desktop-win/build-installer.ps1
   ```
4. The generated installer will be located in `release/SC-Basimbuzi-Management-Portal-Setup-1.0.0.exe`.

## 8. Operational & Maintenance Playbook

1. **Adding New Club Officials**:
   - Navigate to `/admin/users`.
   - Click **Invite User**, enter their official email, full name, and assign their role (`L1_ADMIN`, `L1_SECRETARY`, `COORDINATOR`, etc.).
   - The user receives an automated onboarding link to set their password at `/set-password`.
2. **Monthly Financial Closing**:
   - On the 1st of every month, the automated `monthly-report-job` generates the financial summary for the previous month.
   - The President and Secretary receive the draft via email.
   - The board can open `/admin/reports`, review and refine the statement on the collaborative canvas, and click **Export PDF** for archiving.
3. **Player Contract Renewals**:
   - Navigate to `/admin/contracts`.
   - Select the player or create a new contract from the template.
   - Enter remuneration, dates, and terms.
   - Sign digitally on screen. The system sends an email to the player/guardian for secondary signing. Once both parties sign, an encrypted PDF is locked in Cloudflare R2.
4. **Member Subscription Follow-ups**:
   - Navigate to `/admin/members`.
   - Filter by status **Unpaid** or **Overdue**.
   - Click **WhatsApp Reminders** to launch the assisted sender queue on desktop or send a bulk email reminder via the Brevo broadcast integration.
